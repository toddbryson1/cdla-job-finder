## Operator runbooks

### One-shot prod smoke

```bash
cd ~/projects/cdla-job-finder
npx tsx scripts/smoke-prod.ts
# or, against staging:
npx tsx scripts/smoke-prod.ts --origin https://staging.cdla.jobs
```

Six checks, all read-only, anonymous, no PII:
1. `/api/health/db` returns ok=true with `applied >= expected` AND latest tag matches local journal.
2. Homepage returns 200 + Debbie chat shell renders ("Debbie" + "five minutes" both present).
3. Debbie Q1 LLM round-trip — POST a synthetic "30303" → expect `nextState=Q2_experience` + `fields.homeZip=30303`.
4. Sitemap returns ≥50 `/job/*` URLs.
5. `/api/cron/daily` and `/api/cron/qb-retry` both return 401 without auth.

Exit 0 = all green, 1 = any failure, 2 = runner crash.

### Migration drift check on its own

```bash
curl -s https://www.cdla.jobs/api/health/db | jq
```

Reads `drizzle.__drizzle_migrations` count + latest tag, compares against
local `drizzle/meta/_journal.json` baked at build time. Empty bookkeeping
table or schema-not-found returns `ok=false` with explicit error.
Status code: 200 on ok, 503 on drift.

### Trigger QB retry sweeper manually

```bash
# from local, against prod, with CRON_SECRET in /tmp/cdla-prod-env (chmod 600):
source /tmp/cdla-prod-env
curl -sH "Authorization: Bearer $CRON_SECRET" https://www.cdla.jobs/api/cron/qb-retry | jq
rm -f /tmp/cdla-prod-env
```

Picks up rows where `partner_application_stages.stage = 'submit_queued_for_retry'`
AND `quickbase_next_retry_at <= now()`. Backoff: 0 / 5m / 30m / 2h / 12h / 24h,
max 5 attempts before `submit_failed_permanent`. Carrier-config drift protection
breaks the loop if Sterling realm/token disappears mid-flight.

### Admin funnel — Anderson / Sterling QuickBase

```
https://www.cdla.jobs/admin?key=<ADMIN_KEY>
```

New section "Partner handoff funnel — Anderson / Sterling QuickBase" sits
between driver funnel and per-carrier performance. Cards:
- by-stage counts (claimed / submit_attempted / submit_succeeded / queued_for_retry / failed_permanent)
- total handoffs, retries due now, Sterling-confirmed
- total push attempts, latest submission age (relative — "12m ago")

Single grouped query with FILTER aggregates — sub-50ms even at scale.

### Resume parser — preview tool

When `DEBBIE_RESUME_ENABLED=true`, drivers see a paperclip in the chat.
File goes to `/api/debbie/parse-resume` (multipart), server logs only
field NAMES (never values), Anthropic forces `extract_resume_fields`
tool_use, response is merged into Debbie's running `fields` state with
explicit confirmation in the next assistant turn. PDF + JPEG/PNG/WebP +
TXT supported. DOCX + HEIC deliberately deferred (per parse-resume
test comments).

### Debbie LLM round-trip (manual)

```bash
curl -s -X POST https://www.cdla.jobs/api/debbie/intake \
  -H 'content-type: application/json' \
  -d '{
    "state": "Q1_zip",
    "conversation": [
      {"role": "assistant", "content": "What is your home zip?"},
      {"role": "user", "content": "30303"}
    ],
    "fields": {
      "homeZip": null, "experienceYears": null, "schedule": null,
      "terminatedLastJob": null, "terminationReason": null, "sapStatus": null
    }
  }' | jq
```

Expect `nextState=Q2_experience` + `fields.homeZip="30303"` + a single
assistant `content` string. tool_use is forced server-side; the route
never emits raw model prose.
